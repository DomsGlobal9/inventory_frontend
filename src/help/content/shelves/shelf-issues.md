ScaleEzy never quietly changes shelf numbers to make them agree. Anything it could not do cleanly becomes a **shelf issue**, so a person can look.

- Everyone who can see shelves can read shelf issues.
- Only the owner, an admin or an inventory manager can mark one resolved.

## 1. Open Shelf issues

1. In the menu on the left, click **Shelves**, then the [[1]] **Shelf issues** tab. The orange number on the tab is how many are open.
2. [[2]] **Open** shows what still needs a look. **Resolved** and **All** show older ones.
3. Tick [[3]] **Every location** to see issues from all your stores, not only the one chosen at the top.

![The Shelf issues screen with 2 open issues. The Shelf issues tab is marked 1, the Open, Resolved and All buttons 2, and Every location 3.](1-open.webp "Newest issues are at the top.")

## 2. Read an issue

Each issue shows:

- [[1]] what kind of issue it is, the store and when it happened,
- the item, the shelf address and how many pieces,
- [[2]] what happened, in a sentence,
- [[3]] **Open the shelf**, which opens [Move](/help/shelves/move) with that shelf and item chosen,
- [[4]] **Mark resolved**.

![One issue: NOT FOUND ON THE SHELF is marked 1, the sentence saying a count of FLOOR-C2-1 found 1 fewer Cotton Kurti is marked 2, Open the shelf 3 and Mark resolved 4.](2-read-an-issue.webp "FLOOR-C2-1 and 1 piece at the top right say which shelf and how many.")

The kinds of issue:

| Kind | What happened | What to do |
|---|---|---|
| **Sold from the back room** | A counter sale had no pieces on the shop floor or Not shelved, so it took them from a back room shelf. | Check the back room shelf. Bring more pieces to the shop floor. |
| **Taken off a shelf without a choice** | Stock went out (for example damage or a transfer) and nobody chose a shelf, so ScaleEzy had to pick one. | Check that shelf. Move pieces if it picked the wrong one. |
| **Not found on the shelf** | Someone pressed **Not here** while picking, or a shelf count found fewer pieces. | Look nearby, then [count the shelf](/help/shelves/count). |
| **Count lower than the shelves** | A stock count found fewer pieces than the shelves said, so pieces were taken off a shelf to match. A shelf count that finds more pieces than your stock allows shows this kind too. | Count that shelf again. If a shelf count raised it, correct the stock first. |

## 3. Fix it, then mark it resolved

First fix the real problem: find the pieces, [move](/help/shelves/move) them or [count the shelf](/help/shelves/count). Then:

1. Click **Mark resolved**.
2. [[1]] Type what you found or did. The note is optional, but it helps the next person.
3. Press [[2]] **Resolve**.

![The issue with the note Found it on FLOOR-C2-2 with the dupattas. Moved it back, marked 1, and the Resolve button marked 2.](3-mark-resolved.webp "Cancel closes the note without resolving.")

:::note Resolving does not change anything
Marking an issue resolved only records that someone looked, with the date and the note. It never changes your stock or your shelves.
:::

## 4. Find it later

The issue moves to **Resolved**. It shows [[1]] when it was resolved and your note.

![The resolved issue, with the line Resolved 17 Sept, 5:39 pm and the note, marked 1.](4-resolved.webp "Open the Resolved button to see past issues and what was done.")

## Common problems

:::faq I don't see Mark resolved
Only the owner, an admin or an inventory manager can resolve issues. You can still read them and use **Open the shelf** if you can move stock.
:::

:::faq "Somebody has already marked this as resolved."
Another person resolved it at the same moment. Refresh the page. Nothing else is needed.
:::

:::faq Nothing needs a look
There are no open issues in this store: the shelves and the stock agree. Tick **Every location** to check your other stores.
:::

:::faq The same shelf keeps getting issues
Count the whole shelf with [Count a shelf](/help/shelves/count), and check that everyone scans the shelf label when they move pieces.
:::
